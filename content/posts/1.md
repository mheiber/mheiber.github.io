## What "training" means

When people talk about "training", it often helps to be specific about which phase they mean, as that can affect where PL stuff comes into play. These are in order:
- pre-training: is the phase where a model consumes a ton of data and tries to predict the next token.
- fine-tuning:
    - Fine-tuning is where an LLM is specialized to a domain or task through techniques somewhat similar to those used in pre-training.
    - Fine-tuning can be used to adapt an LLM to particular programming languages or codebases. I've also heard of things like fine-tuning a model to be better at understanding how to "patch" code or work with DSLs..
    - Fine-tuning is cheaper than pre-training but still costs time and money.
    - Fine tuning seems to have gotten less popular:
        - Better models are released frequently, and if you fine-tune then you'll always be behind
        - There's some overlap between what can be done with fine-tuning and what can be done with other techniques like scaffolding (see below) or tools (see below)
    - I like the analogy of fine-tuning an LLM like being adding a new language to GCC: you change the "shallow layers" (front end and back end in compiler speak) without changing the "deep layers" (IR/middle end in compiler speak). Claude does a fine job [saying a lot more about fine-tuning using this compiler analogy](https://claude.ai/chat/c03cd943-a5b6-40bf-8277-6f91c9757960)
    - fine-tuning
    - instruction tuning: this is where an LLM is taught to follow instructions and respond to prompts and (sometimes) taught to use tools (see Tools __TODO__)

## Hallucination

Hallucination is when LLMs say things that aren't true or appear to make untrue presuppositions.

- In a PL context, "hallucination" could mean generating a call to a function that doesn't exist
    - *however*: humans also write calls to functions that don't exist, sometimes with the intention of writing the callee later (top-down reasoning)
- Is generating code that doesn't type-check always or ever "hallucination"? I don't know. "hallucination" is vague and, imo, must be operationalized.
- Augmenting an LLM with the ability to search can reduce hallucination, see RAG and Tools sections.

## Embeddings

An embedding is a representation of data as a higher-dimensional vector.
- There are tools that will turn data (text, image, etc.) into a vector
- vectors can then be used for search: just find geometrically similar vectors and they are likely to represent similar things
- there's sometimes almost an algebra to embeddings: "'King - Man + Woman' results in a vector very close to 'Queen'" (https://arxiv.org/abs/1301.3781)
- embeddings came before llms, but LLM providers sometimes have APIs that enable you to get the embedding for some text that corresponds to the LLM's representation.

## RAG

"RAG" is retrieval-augmented generation. It means doing a search, and adding the results of the search to the prompt. That's it.

RAG based on embeddings:
- There was a fad for a particular kind of RAG where the only form of searched used was based on embeddings
    - You'd take the user's query, generate an embedding, and search a database of embeddings for the closest ones in vector space.
    - Using only embeddings is not usually the best search technique for text. Search engines use a wide variety of techniques such as ranking by a combination of recency, keywords, PageRank, etc., not just embeddings.

You can think of RAG as scaffolding with a single tool (a search tool)

## Reasoning

Someone discovered that if you told an LLM to "take a deep breath" it would be better at math, and then many papers followed.
In some situations, some results indicate that LLMs do better if you say "explain step-by-step" or if you add scaffolding so the LLM writes out a chain of thought.
These techniques and comparisons of the techniques are covered in detail with lots of links in https://www.promptingguide.ai/.
It's contentious how well these techniques actually work or to what extent the models show "reasoning".

## Tools

Providing an LLM "tools" means enabling the LLM to (effectively) call functions:
- I said above that the output of an LLM is (from a high-level point of view) a string. So what actually happens when you give an LLM tools is that the LLM's output includes *instructions to call functions*. Usually some library or API then interprets this output to actually invoke the functions and then call the LLM again with the return values as part of the new prompt.
    - An immediate implication of "the output is a function" is that parameter types and return types of such functions are serialized.
- A library for tools will do things like add information about tools to the prompt (such as their parameter and return types).
